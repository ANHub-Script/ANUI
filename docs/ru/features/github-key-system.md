# Ключи через GitHub

Провайдер ключей `github` выдаёт **по одному ключу на устройство** сроком на **24 часа**; игрок генерирует его сам на вашем сайте GitHub Pages. База ключей — это один JSON-файл в репозитории GitHub, поэтому не нужен ни собственный сервер, ни сторонний сервис ключей.

- **На устройство** — ключ привязан к отпечатку, полученному из HWID исполнителя.
- **24 часа** — срок жизни настраивается, по умолчанию 24.
- **Перегенерация в любой момент** — новая генерация сразу убивает предыдущий ключ.
- **В реальном времени** — библиотека читает базу напрямую с `raw.githubusercontent.com` при каждой проверке, с обходом кеша.

## Как это работает

```
Исполнитель                  Ваш сайт GitHub Pages          Репозиторий GitHub
-----------                  ---------------------          ------------------
SHA-256(HWID)[0..31]
   │  «Get key» копирует
   │  .../getkey/#fp=<отпечаток>
   ▼
   ├──────────────────────▶ генерирует ANUI-XXXXX-XXXXX-XXXXX
   │                        подписывает через HMAC-SHA256
   │                        пишет keys[<отпечаток>] ────────▶ db/keys.json
   │
   ◀── игрок вставляет ключ обратно в окно ввода
   │
   └── читает db/keys.json ◀────────────────────────────────── raw.githubusercontent.com
       проверяет отпечаток, срок и подпись
```

Сырой HWID никогда не покидает исполнителя. В публичный репозиторий попадает только усечённый SHA-256 от него — отпечаток.

Обойти истечение срока мешают две вещи:

- **Время берётся у GitHub.** И страница генератора, и библиотека читают HTTP-заголовок ответа `Date`, поэтому перевод системных часов назад не продлевает ключ.
- **Каждая запись подписана.** `sig = HMAC-SHA256(secret, "key|fingerprint|issued_at|expires_at")`, усечённая до 32 hex-символов. Ручная правка базы делает запись недействительной.

## Настройка

### 1. Создайте базу

Закоммитьте начальный файл в репозиторий, который будет хранить ключи:

```json
{
  "version": 1,
  "updated_at": 0,
  "ttl_hours": 24,
  "keys": {}
}
```

Путь по умолчанию — `db/keys.json`. Не добавляйте его в `.gitignore`: генератор коммитит в него, а библиотека его читает.

::: tip Используйте отдельный репозиторий
Если база лежит в своём репозитории (например, `ВашеИмя/ANUI-Keys`), токен со страницы генератора не сможет добраться до исходников библиотеки. Это самая полезная мера предосторожности в такой схеме.
:::

### 2. Создайте токен

В GitHub: **Settings → Developer settings → Personal access tokens → Fine-grained tokens**.

| Параметр | Значение |
| --- | --- |
| Тип | **Fine-grained**, ни в коем случае не classic |
| Доступ к репозиториям | Только репозиторий с базой ключей |
| Разрешения | **Contents → Read and write**, и больше ничего |
| Срок действия | Как можно короче, затем ротация |

### 3. Соберите конфиг генератора

```bash
node build/keygen-config.js
```

Вопросы охватывают репозиторий, формат ключа, срок жизни, задержку и оформление; токен и HMAC-секрет вводятся скрыто и никогда не выводятся в терминал. Скрипт записывает `docs/public/getkey/config.js` и печатает HMAC-секрет вместе с готовым блоком `KeySystem`.

Неинтерактивно, для CI:

```bash
ANUI_GH_TOKEN=github_pat_... ANUI_HMAC_SECRET=ваш-секрет node build/keygen-config.js --yes
```

| Флаг | Переменная окружения | По умолчанию |
| --- | --- | --- |
| `--owner` | `ANUI_GH_OWNER` | `ANHub-Script` |
| `--repo` | `ANUI_GH_REPO` | `ANUI` |
| `--branch` | `ANUI_GH_BRANCH` | `main` |
| `--db-path` | `ANUI_DB_PATH` | `db/keys.json` |
| `--prefix` | `ANUI_KEY_PREFIX` | `ANUI` |
| `--ttl` | `ANUI_TTL_HOURS` | `24` |
| `--cooldown` | `ANUI_COOLDOWN` | `0` |
| `--brand` | `ANUI_BRAND` | `ANUI` |
| `--discord` | `ANUI_DISCORD` | — |
| `--site-url` | `ANUI_SITE_URL` | выводится из owner и repo |
| `--token` | `ANUI_GH_TOKEN` | запрашивается скрыто |
| `--secret` | `ANUI_HMAC_SECRET` | запрашивается скрыто (генерируется, если пусто) |

### 4. Опубликуйте страницу

Генератор лежит в `docs/public/getkey/`, который VitePress копирует как есть, поэтому после публикации документации он доступен по адресу:

```
https://<owner>.github.io/<repo>/getkey/
```

### 5. Подключите в скрипте

```lua
ANUI:CreateWindow({
    Title = "My Hub",
    Folder = "MyHub",
    KeySystem = {
        Note = "Сгенерируйте ключ для этого устройства. Действует 24 часа.",
        SaveKey = true,
        API = {
            {
                Type = "github",
                Owner = "ANHub-Script",
                Repo = "ANUI-Keys",
                Branch = "main",
                DBPath = "db/keys.json",
                URL = "https://anhub-script.github.io/ANUI/getkey/",
                Secret = "секрет-напечатанный-keygen-config",
            },
        },
    },
})
```

`Secret` должен совпадать с HMAC-секретом в конфиге генератора, иначе любой ключ не пройдёт проверку подписи.

## Аргументы провайдера

| Поле | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `Type` | `string` | — | Должно быть `"github"`. |
| `Owner` | `string` | — | Пользователь или организация — владелец репозитория с базой. |
| `Repo` | `string` | — | Репозиторий с базой. |
| `Branch` | `string` | `"main"` | Ветка для чтения. |
| `DBPath` | `string` | `"db/keys.json"` | Путь к базе внутри репозитория. |
| `URL` | `string` | — | Публичный адрес страницы генератора. **Get key** копирует его с добавленным `#fp=<отпечаток>`. |
| `Secret` | `string` | — | HMAC-секрет. Пустое значение отключает проверку подписи (не рекомендуется). |
| `Folder` | `string` | `Folder` окна | Подставляется ANUI; задаёт, куда пишется офлайн-кеш. |

`Icon`, `Title` и `Desc` работают как у любого другого провайдера и влияют только на строку в списке **Get key**.

## Что видит игрок

1. Открывает меню — появляется окно ввода ключа.
2. Нажимает **Get key** и выбирает строку провайдера. Ссылка, уже содержащая отпечаток этого устройства, копируется в буфер обмена.
3. Открывает её в браузере, нажимает **Generate key**, копирует ключ.
4. Вставляет его в окно ввода.

При `SaveKey = true` принятый ключ записывается в `ANUI/<Folder>/<hwid>.key`, поэтому при следующем запуске окно не появится, пока ключ не истечёт.

## Проверка

Библиотека сначала проверяет ключ онлайн:

1. `GET https://raw.githubusercontent.com/<owner>/<repo>/<branch>/<path>?cb=<уникальное>` — обход кеша побеждает многоминутный кеш CDN, именно это делает чтение мгновенным.
2. Находит `keys[<отпечаток>]`. Нет записи или стоит `revoked` — значит, у устройства нет ключа.
3. Сравнивает введённый ключ с сохранённым — перегенерированный ключ провалится здесь.
4. Проверяет подпись, затем срок по заголовку `Date` от GitHub.

При успехе результат кешируется в `ANUI/<Folder>/<отпечаток>.keycache`. Кеш — только запас на случай, когда сам HTTP-запрос не удался: он не может подтвердить ключ, который не подтвердил сервер, никогда не живёт дольше `expires_at` и удаляется при любом отказе со стороны сервера.

## Формат базы

```json
{
  "version": 1,
  "updated_at": 1774440000,
  "ttl_hours": 24,
  "keys": {
    "a1b2c3d4e5f60718293a4b5c6d7e8f90": {
      "key": "ANUI-7GKQ2-XM4TB-9WHZP",
      "sig": "4f1c9ab27d3e5f60718293a4b5c6d7e8",
      "issued_at": 1774440000,
      "expires_at": 1774526400,
      "regen": 3,
      "revoked": false
    }
  }
}
```

| Поле | Значение |
| --- | --- |
| `key` | Ключ, который вставляет игрок. Один на устройство — новый его перезаписывает. |
| `sig` | `HMAC-SHA256(secret, "key\|fingerprint\|issued_at\|expires_at")[0..31]`. |
| `issued_at` / `expires_at` | Unix-секунды по часам GitHub. |
| `regen` | Сколько раз это устройство генерировало ключ. |
| `revoked` | Поставьте `true` вручную, чтобы заблокировать устройство, не удаляя его историю. |

Ключи используют алфавит `0123456789ABCDEFGHJKMNPQRSTVWXYZ` — без `I`, `L`, `O` и `U` — чтобы ключ нельзя было перепутать на слух.

::: tip Чистка
Истёкшие записи безвредны, но файл растёт. Удаляйте старые записи когда угодно; Contents API перестаёт встраивать содержимое файла примерно после 1 МБ, и генератор сообщит, если вы до этого дойдёте.
:::

## Безопасность

::: danger Токен публичен
GitHub Pages — статический хостинг. Токен из `config.js` отдаётся браузеру каждого посетителя. Перемешивание в этом файле нужно лишь для того, чтобы сканер секретов GitHub не отозвал токен автоматически, и чтобы отбить желание скопировать его мимоходом — **это не шифрование**. Любой, кто прочитает файл, восстановит токен и сможет выпускать свои ключи или писать всюду, куда токен достаёт.

Поэтому:

- Используйте **fine-grained** токен, ограниченный только репозиторием с ключами, с единственным разрешением **Contents → Read and write**.
- Держите базу в **отдельном репозитории** от исходников библиотеки.
- Задайте срок действия и ротируйте токен.
- Считайте это *защитой от случайных прохожих*, а не сервером лицензий.
:::

Если позже захотите схему без утечек, перенесите запись за небольшой прокси — Cloudflare Worker или GitHub Action на `repository_dispatch` — и удалите токен из `config.js`. В Lua-библиотеке менять ничего не придётся: она только читает базу.

HMAC-секрет лежит в том же файле и восстанавливается так же легко. Его польза в другом: базу нельзя править руками, не сломав подписи записей, и именно это не даёт украденной или самодельной записи пройти проверку.

## Диагностика

| Симптом | Причина |
| --- | --- |
| Страница пишет *Generator not configured* | `config.js` всё ещё пример. Запустите `node build/keygen-config.js`. |
| *the token is invalid or expired* | Токен отозван, истёк или его поймало сканирование GitHub. Создайте новый. |
| *the token lacks Contents: read and write* | Не то разрешение или токен не привязан к этому репозиторию. |
| *the repository, branch or path does not exist* | Проверьте `owner`, `repo`, `branch` и `dbPath`; fine-grained токен не видит репозитории вне своей области. |
| *Signature mismatch* на странице | Базу правили вне страницы или сменился секрет. Перегенерируйте. |
| *Key signature is invalid* в игре | `Secret` в скрипте отличается от секрета генератора. |
| *No key issued for this device yet* | У устройства нет записи. Нажмите **Get key**, сгенерируйте, вставьте. |
| Ключ отклоняется сразу после генерации | Библиотека прочитала кешированную копию — нажмите отправку ещё раз; запросы идут с обходом кеша и разрешаются за секунды. |
| В игре ничего не происходит | У исполнителя нет `request`/`gethwid`. Нужны оба. |
